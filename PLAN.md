# Fontlord — план разработки

Документ описывает архитектуру, этапы разработки и состояние проекта.
Используется как рабочий чек-лист: отметка `[x]` означает, что этап завершён
и покрыт тестами.

## 1. Цели

Fontlord — редактор шрифтов, в котором символ рисуется обычным растровым
способом (мышь/перо), но специальные кисти на лету превращают «закорюшки» в
настоящие векторные контуры TrueType.

Ключевые требования:

| # | Требование | Реализация |
|---|------------|------------|
| 1 | Сетка всех символов Unicode с группировкой | `fontlord_core::unicode`, панель «Символы» |
| 2 | Поиск по именам, кодам и символам | `UnicodeIndex::search`, поле поиска |
| 3 | Рисование как в растре | Холст `<canvas>`, штрихи с нажимом |
| 4 | Кисти преобразуют рисунок в вектор | `fontlord_core::stroke` + `outline` |
| 5 | Промежуточные сохранения проекта | Формат `.fontlord`, `fontlord_core::project` |
| 6 | Экспорт готового шрифта | `fontlord_ttf`, таблицы `glyf`/`cmap`/… |
| 7 | Задел под лигатуры и диакритику | `fontlord_core::features`, поля модели |

## 2. Архитектура

```
fontlord/
├── crates/
│   ├── fontlord-core/     домен: модель, кисти, контуры, индекс Unicode, формат проекта
│   ├── fontlord-ttf/      сборщик шрифтов TrueType (таблицы glyf, cmap, name, OS/2, kern)
│   └── fontlord-cli/      консольные утилиты: info, glyphs, export, demo
├── src-tauri/             оболочка Tauri: IPC-команды, состояние, история изменений
├── ui/                    фронтенд: React + TypeScript + Vite
└── tools/                 скрипты сборки окружения, генерация иконок, снимки экрана
```

Принципы:

* **Ядро не зависит от Tauri.** Вся логика шрифтов живёт в библиотеке, её можно
  использовать в CLI-конвертере или в сервисе.
* **Штрих — источник истины, контур — производное.** Пользователь редактирует
  штрихи; контуры пересчитываются движком кистей при каждом изменении. Это
  позволяет менять точность аппроксимации без потери исходного рисунка.
* **Ориентация контуров задана явно.** Внешние контуры имеют положительную
  ориентированную площадь, внутренности — отрицательную. Благодаря этому
  правило ненулевой намотки TrueType корректно склеивает перекрывающиеся мазки
  и вырезает внутренности замкнутых контуров.
* **IPC — тонкий.** Команды не содержат логики, они только маршрутизируют
  вызовы в ядро.

## 3. Этапы

### Этап 1. Каркас workspace и инфраструктура — `[x]`

* Cargo workspace из трёх крейтов, единые версии и профили.
* Скрипт `tools/fetch-sysdeps.sh`: установка системных зависимостей Tauri
  (webkit2gtk-4.1 и пр.) в локальный sysroot без root-доступа.
* Скрипт `tools/env.sh`: переменные окружения для сборки.
* Генерация иконок приложения (`tools/gen_icons.py`).

### Этап 2. Доменное ядро — `[x]`

* `geometry.rs`: точки, векторы, пересемплирование, сглаживание Катмулла–Рома,
  упрощение Рассела–Дойла, ориентированная площадь.
* `model.rs`: проект, глиф, штрих, контур, метрики, кернинг, лигатуры, метки.
* `stroke.rs`: движок кистей — очистка шума, сглаживание, пересемплирование,
  расчёт полуширины, построение полигонов.
* `outline.rs`: аппроксимация полигонов квадратичными кривыми (алгоритм
  Шнейдера) с сохранением острых углов.
* `brush.rs`: пять кистей (перо, маркер, каллиграфия, мягкая, ластик) и пресеты.
* `project.rs`: версионированный формат `.fontlord`, атомарная запись.
* `features/`: расчёты лигатур и привязки диакритики (задел под будущее).

### Этап 3. Индекс Unicode — `[x]`

* Имена символов (`unicode_names2`), блоки (`unicode-blocks`), категории
  (`unicode_categories`).
* Ленивая построение индекса с кэшированием в статике.
* Поиск по подстроке имени, по коду (`U+0041`) и по самому символу.

### Этап 4. Сборщик TrueType — `[x]`

* Таблицы `head`, `hhea`, `maxp`, `hmtx`, `cmap` (форматы 4 и 12), `glyf`,
  `loca`, `name`, `OS/2`, `post`, `kern`.
* Нормализация контуров под правила TrueType (подразумеваемые точки на кривой).
* Проверка результата независимыми инструментами: `ttf-parser` и `fontdue`.

### Этап 5. Оболочка Tauri — `[x]`

* Состояние приложения, история изменений (undo/redo) на снимках проекта.
* IPC-команды: Unicode-индекс, глифы, штрихи, метрики, проект, экспорт.
* Диалоги открытия/сохранения/экспорта.

### Этап 6. Интерфейс — `[x]`

* Сетка Unicode с фильтром блоков, поиском и постраничной подгрузкой.
  Список блоков и сетка символов делят высоту в отношении 1:2.
* Холст редактора: em-квадрат, направляющие (ascender/cap/x-height/baseline/
  descender), ширина продвижения, масштаб.
* Панель кистей с пресетами и параметрами, панель метрик, список штрихов,
  панель параметров шрифта.
* Предпросмотр шрифта: реальная сборка TTF и отрисовка через `FontFace`.
* Меню верхнего уровня (Файл, Правка, Вид, Кисти, Справка) с навигацией
  стрелками и подсказками горячих клавиш.
* Горячие клавиши на все основные действия; заголовок окна отражает
  текущий проект (`Fontlord — имя.fontlord`).

### Этап 7. Контроль качества — `[x]`

* Юнит-тесты ядра: геометрия, ориентация контуров, замкнутые штрихи, ластик,
  формат проекта, индекс Unicode, лигатуры, диакритика.
* Интеграционные тесты сборщика шрифта: разбор `ttf-parser`, растеризация
  `fontdue`.
* Сборочные примеры: `export_sample` (демонстрационный `.ttf`) и
  `render_glyphs` (растеризация глифов в PPM для визуальной проверки).
* Консольные утилиты `fontlord-cli`: сводка по проекту, список глифов,
  сборка шрифта, генерация демонстрационного проекта.

### Этап 8. Дальнейшее развитие — `[ ]`

* **Лигатуры.** Модель и расчёты готовы (`features::ligatures`), не хватает
  интерфейса сборки лигатуры из глифов и записи правил `liga` в `GSUB`.
* **Диакритика.** Модель и расчёты готовы (`features::marks`), требуется
  интерфейс расстановки якорей и поддержка составных глифов в `glyf`.
* **Редактирование узлов.** Прямое редактирование контуров (перетаскивание
  управляющих точек) поверх штрихов.
* **Кривые Безье.** Сейчас контуры квадратичные (формат TrueType); поддержка
  кубических кривых потребует варианта OTF (`CFF`).
* **Слои и цвет.** Несколько слоёв, альфа-канал, обводка и градиенты.
* **Автосейв.** Периодическое сохранение проекта в отдельный файл восстановления.
* **Совместная работа.** Синхронизация проекта между устройствами.

## 4. Проверка качества

```bash
source tools/env.sh          # системные зависимости и пути сборки

cargo test --workspace       # юнит- и интеграционные тесты
cargo clippy --workspace --all-targets
cargo fmt --all -- --check

cd ui && pnpm install && pnpm build   # сборка фронтенда
cargo build -p fontlord               # сборка приложения

# Сквозная проверка без графического интерфейса:
cargo run -p fontlord-cli -- demo /tmp/demo.fontlord
cargo run -p fontlord-cli -- export /tmp/demo.fontlord /tmp/demo.ttf
cargo run -p fontlord-ttf --example render_glyphs -- /tmp/demo.ttf /tmp/glyphs.ppm
```

## 5. Риски и ограничения

| Риск | Статус | Комментарий |
|------|--------|-------------|
| Сборка `glyf` вручную | снят | Результат проверяется `ttf-parser` и `fontdue` |
| Совместимость OTF/CFF | в работе | Сборщик TrueType; CFF запланирован |
| Логика булева вычитания | учтено | Ластик удаляет штрихи целиком, а не область |
| Производительность индекса Unicode | приемлемо | Индекс строится один раз (~0.2 с), поиск — по буферу имён |
